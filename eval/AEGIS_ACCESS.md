## Actual architecture and inference

The model combines frozen DINOv2 plus learned noise/frequency features, a small learned frame-pair CNN with a temporal transformer, and temporal derivatives of projected DINOv2 features. The motion module is **not RAFT or VideoMamba**, despite stale comments naming them; the actual implementation is ordinary PyTorch CNN/transformer code. A learned fusion head returns a sigmoid score. Published parameter counts are 94,956,811 total and 9,231,883 trainable. [Model code](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/detector_model.py), [motion code](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/motion_branch.py).

The [entry point](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/inference.py) requests sixteen frames. The [decoder](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/utils/video_io.py) defaults to a randomly located four-second window, uniformly samples sixteen indices within it, resizes each RGB frame to 224×224 with OpenCV linear interpolation, and applies ImageNet normalization. It rejects inputs below eight frames, a 128-pixel shortest side or one second. This is not a whole-video scan. The CLI uses `ai_probability > 0.5`; training metrics use `>= 0.5`, a tie distinction to record prospectively.

## Required safeguards before any bounded screen

1. **Safe, complete weights.** Stock inference explicitly calls `torch.load(..., weights_only=False)` and continues with random weights when the checkpoint is absent. Do neither. A future authorized run must hash-check the file, use restricted `weights_only=True`, reject unreviewed globals, require all expected tensor keys/shapes under strict loading, and preserve the extracted tensor state as safetensors. The training saver writes `model_state`, optimizer state and ordinary metrics, so restricted extraction is plausible but untested.
2. **Remove dependence on an author's home directory.** `pixel_branch.py` hard-codes a DINOv2 safetensors path under `/home/musap.yildiz/.cache/...`; setting `AEGIS_BASE_DIR` does not repair it. The constructor tries to read this before loading the complete detector checkpoint. The saved `model.state_dict()` should include the registered frozen backbone; architecture-only construction followed by verified complete strict loading may avoid an unnecessary second weight download. This must be verified, not assumed. Preserve architecture and trained math. [Pixel code](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/pixel_branch.py).
3. **Deterministic sampling and strict decoding.** Freeze the official sampling mode and seed, or explicitly declare use of its built-in centered-window option as an adaptation. Record source indices/timestamps and actual insert coverage. OpenCV fallback currently fills failed requested frames with the previous frame or zeros; those failures must become recorded errors, not authentic-looking negative predictions.
4. **CPU contract first.** The CLI supports CPU; OpenCV is a fallback when Decord is absent. Required inference operations appear feasible on this Mac, but no latency/memory result exists here. MPS is accepted as a manual device string but is neither auto-selected nor validated; complex FFT needs an explicit compatibility/equivalence check. No CUDA-specific model extension was found. The reported 0.13-second inference and 2.19 GB peak memory are author measurements on a Tesla V100, not Mac estimates.
5. **Do not inherit confidence claims.** The UI's low-confidence condition `disagreement > 0.4` is unreachable: disagreement is the population variance of three values in [0,1], bounded above by 2/9. The sigmoid and confidence labels are not calibrated probabilities. Additionally, `fftshift` omits `dim`, shifting the flattened frame-batch axis as well as spatial axes. This trained computational quirk must be preserved for a faithful checkpoint test; changing it is a different candidate.

## What the reported evidence supports

The model card advertises validation AUROC 0.9980 and FPR 2.18%. The repository describes 43,857 training and 4,908 validation samples from older generation collections plus selected newer material, but acknowledges uncertain origins for some local Veo/Kling/Sora data. Its checkpoint discussion explicitly compares AEGIS and GenBuster results across epochs. These are author-reported development-influenced results, not independent verification. [Publisher description](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/README.md).

At the default decision rule, the published GenBuster++ result is **73.6% recall and 13.5% FPR**, AUROC 0.8695; the motion branch alone has AUROC 0.5116. [Published metrics](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/results/phase2/ablation_genbuster.json). The [comparison table](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/results/phase2/full_comparison.md) reports 73.85% recall on 436 AEGIS videos and 62.75% on a 51-clip Sora-only test. Neither the inspected code nor results establish matched recompression robustness, modern unseen-generator independence, low deployment false-positive rates, or brief-insert sensitivity. A training/data-selection audit and frozen development protocol are separate in `AEGIS_EVALUATION_PROTOCOL.md`.

**Decision:** this is a more concrete local experimental route than a placeholder or gated checkpoint, subject to the strict loading contract above. It warrants at most a predefined development screen if authorized; it does not warrant integration, threshold/epoch/branch sweeps or reuse of consumed holdout data. Official text/code inspected totals about 180 KB; source URLs and hashes are preserved under `sources/aegis-readonly/access.json`.

## Subsequent authorized preparation

The parent task subsequently downloaded and verified the official best checkpoint, found no unsafe globals, restricted-loaded it with `weights_only=True`, and confirmed every tensor identical after safetensors conversion. The resulting 379,894,560-byte file has SHA-256 `c464af41b7528f18c1a3de748dde4dc5171aafaf8469c8848036ac45329ae474`; its 467 tensors include 174 backbone entries. See `sources/aegis-safe-conversion-receipt.json` for the actual receipt. This safe extraction does not by itself establish architecture compatibility or accuracy.

`scripts/eval-aegis.py` and an unchanged pinned source subset under `vendor/aegis` now prepare the fixed CPU-only screen. They require the exact converted hash, complete strict state loading, centered four-second/16-frame sampling, one clip per batch, four Torch threads, strict decoding and the main score at `>= 0.5`. The centered setting matches the authors' raw-video ablation loader, despite the random convenience-CLI default. [Official benchmark loader](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/ablation_eval.py#L228). No tensor computation was changed. Syntax, registered-cohort rejection and gate-integrity checks passed without importing the model. Model execution remains separate from this preparation record and requires the declared three-control gate before the larger cohort.

The authorized gate subsequently loaded all 467 expected tensors strictly and processed all three clips without errors. The whole generated clip was positive and CGI negative, but the mixed clip was negative despite eight sampled insert frames. Runtime was 1.48–1.62 seconds per clip on CPU, excluding setup, with process peak RSS about 1.78 GB. This resolves basic Mac runtime feasibility, not detection reliability. The failed gate stopped the larger 105-file stage. The frozen evaluator, source snapshot, raw outputs and strict-load receipt remain preserved; [the result report](./AEGIS_DEVELOPMENT.md) records the stopped decision.
