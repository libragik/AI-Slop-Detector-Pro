# BusterX access and evaluation assessment

Checked 2026-09-04. Research only: no checkpoint downloaded, account created, terms accepted, contact information shared, or inference performed. **Not selected for this implementation:** the published detection tradeoff, unresolved exact overlap, gated access and required Mac port do not justify pursuing it now. No BusterX accuracy claim is made from our own testing.

## Candidate and access

The assessed candidate is the authors' June 2026 **BusterX++**, a trained image/video forensic MLLM based on Qwen3.5-4B. The official [repository](https://github.com/l8cv/BusterX/tree/734e280c894caca5eafa79e40aa08e2be1b30a85) points to [l8cv/BusterX-plusplus](https://huggingface.co/l8cv/BusterX-plusplus). Pin model revision `4ec963385d7529015cb079afcf7ab2026cf60327` before any future experiment.

The [model metadata](https://huggingface.co/api/models/l8cv/BusterX-plusplus?blobs=true) lists three BF16 safetensor shards totaling 10,350,018,536 bytes. The model page requires login and agreement to share contact information; an unauthenticated config request returned HTTP 401. Hugging Face lists no deployed inference provider for this model. A boolean check through standard `huggingface_hub.get_token()` found no configured token. No other credential locations were searched.

The official author's other listed release, [BusterX++-2025](https://huggingface.co/l8cv/BusterX-plusplus-2025), is also gated. Its Qwen2.5-VL-7B weights total 16,584,414,544 bytes at revision `ef36955833ce89764707ecb32e0956346236a12b`. The legacy official `BusterX_plusplus` URL redirects to this release. May 2025 repository history announced coming availability; July 2025 linked only the ++ checkpoint. No currently accessible nongated original BusterX weights were found through the official release paths.

## Training separation and limits

The June 2026 [BusterX paper, sections 2–3 and Table 2](https://arxiv.org/html/2505.12620v8), separates GenBuster-200K training from GenBuster-Bench. Training video generators are CogVideoX, EasyAnimate, HunyuanVideo, and LTX-Video; ID tests those generators on separately constructed clips. OOD contains commercial generators, while Wild contains 150 selected social-circulating videos from newer engines, including Seedance 2.0. All tracks undergo uniform postprocessing. The authors identify OpenVid-1M as the real-video source. The paper tests JPEG and frame removal; it does not supply a controlled Instagram upload/download codec comparison.

The revised [BusterX++ paper, section 5](https://arxiv.org/html/2507.14632v4), describes 10,000 training samples from GenBuster-200K and So-Fake-Set, and calls evaluation generators substantially disjoint. It reports GenBuster Wild fake recall of 70.7% and ID real specificity of 87.0%. Its perturbation tests use JPEG quality 70, noise, blur, and a cascade; aggregate cross-modal accuracy decreases from 81.8% to 75.3%. These author results support investigation, not a deployment guarantee or an exact training cutoff for every generator. The paper's input is uniformly sampled video at 2 FPS with 64 tokens per frame.

The current [training script](https://github.com/l8cv/BusterX/blob/734e280c894caca5eafa79e40aa08e2be1b30a85/scripts/train_dapo.sh) reads separate `genbuster_unified_image.jsonl` and `genbuster_unified_video.jsonl`; the [evaluation script](https://github.com/l8cv/BusterX/blob/734e280c894caca5eafa79e40aa08e2be1b30a85/scripts/eval_genbuster_bench.sh) reads `genbuster_bench.jsonl`. There is no evidence here that the benchmark was intentionally reused as training. However, public naming and author statements do not independently establish exact-clip, prompt, creator, model-selection, or base-model pretraining separation for the released checkpoint. Our own development/calibration/holdout split is only a split inside that public benchmark. Treat any BusterX run on it as a benchmark replication until those gaps are resolved or independent sources are evaluated.

## License and Mac feasibility

The actual [code license](https://github.com/l8cv/BusterX/blob/734e280c894caca5eafa79e40aa08e2be1b30a85/LICENSE) is BSD-3-Clause, with notice preservation and non-endorsement requirements, without a noncommercial restriction. The model card declares MIT, but contains no substantive model documentation; any additional gated conditions have not been reviewed or accepted. Confirm the displayed conditions before authorizing access. Do not infer a commercial prohibition merely from gating, or infer that a license label replaces access conditions.

This Mac reports 256 GiB physical memory, so nominal capacity exceeds the 10.35 GB weight payload. Runtime and latency remain unverified. The authors' [environment](https://github.com/l8cv/BusterX/blob/734e280c894caca5eafa79e40aa08e2be1b30a85/pyproject.toml) pins Transformers 5.8.1, Torch 2.11, vLLM and CUDA-oriented kernels, including a Linux-only causal-conv1d wheel; the stock command is not a demonstrated Mac route. The eight-H100 default is not proof that one inference requires eight GPUs. A separate minimal Transformers CPU/MPS adapter is plausible, but would need audit, compatible non-CUDA operators, bounded generation, and measured throughput. The existing specialist environment should remain unchanged.

## Retained future evaluation plan, not active work

1. Review the gate, fetch only the pinned safetensors/config/tokenizer files with hashes, and use an isolated inference environment. Never enable remote model code or unpickle checkpoints. Preserve official prompt, preprocessing and decoding behavior; report any necessary deviations.
2. Run a two-clip development contract on known real/generated pixels to validate output parsing, memory and latency. Stop if the required model operators cannot run reliably on CPU/MPS; do not substitute an unverified quantized third-party checkpoint.
3. Run the same original 35 development clips, their 70 repost simulations, and the six CGI/mixed controls before integrating anything. Report actual model predictions, AI recall, FPR, abstention, scan/pass failures, source-group uncertainty, and native-versus-transformed differences. An OR fusion requires its own false-positive and repost evaluation.
4. Add independently documented generated clips and camera footage outside GenBuster, including actual social downloads and short inserts. Keep source families and derivatives together. Verify overlap where possible, freeze all candidate decisions, then use untouched calibration/holdout under a preregistered rule. Public-paper scores cannot replace this measured pixel evaluation.
