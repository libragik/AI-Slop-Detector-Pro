# DINOv2 ViT-S/14 training backbone

Checked 2026-09-05 UTC. **An official, ungated, commercially usable small backbone is available. Frozen DINOv2 features with a trained temporal head are justified as one inexpensive supervised baseline, not as an established detector or a new forensic representation.** No weights were downloaded, no model was constructed or run, and no training occurred.

## Exact selected release

Use **`facebook/dinov2-small`**, the ordinary distilled ViT-S/14 without register tokens, at Hugging Face revision **`ed25f3a31f01632728cabb09d1542f84ab7b0056`**. The official model API reports `private:false`, `gated:false` and Apache 2.0. Its config has 12 transformer layers, 6 attention heads, hidden dimension 384 and patch size 14. Safetensors metadata declares 22,056,576 FP32 parameters. [Pinned model](https://huggingface.co/facebook/dinov2-small/tree/ed25f3a31f01632728cabb09d1542f84ab7b0056).

## Faithful, bounded extraction recipe

1. Acquire only the pinned safetensors/config/processor files into an isolated model directory; verify exact hashes and retain the publisher card/license. Load built-in `Dinov2Model` and `BitImageProcessor` from the pinned local files, with `local_files_only=True`, `use_safetensors=True` for the model, and no remote code. Require empty missing/unexpected/mismatched loading-key lists, exact tensor dimensions, finite parameters and a complete state receipt. No classifier head, register variant, automatic alternate weights, quantization or fine-tuning of the backbone.
2. Decode frames strictly to RGB and retain actual timestamps/indices. The selected [processor config](https://huggingface.co/facebook/dinov2-small/blob/ed25f3a31f01632728cabb09d1542f84ab7b0056/preprocessor_config.json) uses bicubic resize of the shortest edge to 256, center crop 224×224, conversion to RGB, rescale by 1/255, and ImageNet mean `[.485,.456,.406]` / standard deviation `[.229,.224,.225]`. Use the slow built-in processor, not an unreviewed fast/GPU replacement. This matches the spatial sizes in Meta's standard evaluation transform; it is not a whole-frame transform. It can discard substantial border content, especially in portrait footage. Missing decode or unsupported coverage must remain an error/abstention, never a negative label.
3. Use FP32, `attn_implementation="eager"`, `model.eval()`, all backbone parameters `requires_grad=False`, and inference mode. Start the contract on CPU with four Torch threads and a small frame microbatch. Cache **`pooler_output`**, the final layer-normalized CLS token, shape `[frames,384]`; do not substitute an ImageNet logit, patch mean or an unnormalized hidden layer. Input 224×224 produces 256 image patches plus CLS. The config's `image_size:518` describes the pretrained positional grid; the built-in model interpolates it for 224 input. Do not overwrite it with 224.
4. Freeze the video sampling/window/aggregation policy separately before the experiment. The backbone has no temporal sampler or video score. Cache only embeddings and processing receipts; origin labels, paths, generator identifiers, prompts and compression names remain outside model inputs. Every derivative stays with its source group. No metadata fallback or new quality-specific branch.

The inspected installed implementation is **Transformers 4.57.6**, with Torch 2.8.0, torchvision 0.23.0, safetensors 0.8.0 and Pillow 12.3.0. The installed DINOv2 model/config and Bit processor files matched their official v4.57.6 source bodies exactly. In this version, positional embeddings use explicit-size bicubic interpolation. This is the frozen HF runtime recipe; it must not be advertised as numerically identical to an older Meta offset-based interpolation implementation without an equivalence test. Keep extraction identical for training, development and any later deployment.

## CPU/MPS feasibility and required contract

The HF path uses ordinary PyTorch layers and does not require CUDA, xFormers, Flash Attention or the full Meta training environment. Meta's general training/evaluation setup was tested on older Linux/CUDA versions; that is not proof of this Mac's runtime. PyTorch 2.8 [documents MPS](https://docs.pytorch.org/docs/2.8/notes/mps.html), and the existing hardware audit found it available. Neither establishes this exact model's successful forward or throughput.

Before batch extraction, verify complete safe loading, exact input/output shapes and finite outputs on CPU. Compare the same fixed frames with MPS FP32, measuring maximum/relative feature differences, downstream head-score sensitivity, peak memory and latency. Do not enable silent unsupported-op CPU fallback. A failure leaves the explicit CPU route or stops the experiment; it does not authorize changing weights, precision, processor or attention implementation. A frozen-feature head can train on CPU cheaply; only its parameters should change. Its own bounded backward/save/resume contract must verify finite gradients, actual updates, reproducibility and unchanged backbone hashes. Full-corpus timing should be estimated from measured frame throughput, not model size or unified-memory capacity.

## Distinct hypothesis and limits

A concrete minimal candidate is a training-only standardized vector formed by concatenating the **384-dimensional temporal mean, population standard deviation, and mean absolute adjacent difference** of CLS features, followed by one trained linear logit: 1,152 feature values and 1,153 head parameters. This is a proposed baseline for the parent to preregister, not a frozen experiment here. The temporal component measures representation changes under the chosen sampling cadence; it is not optical flow, physical velocity, provenance or an interval label. Frame-spacing and clip-length confounds need explicit controls. Probability calibration and a decision threshold must be chosen separately using permitted training/development allocations and then frozen.

The useful new hypothesis is whether this simple, inspectable supervised head can learn a boundary from the selected weak-label training pool that survives compression and independently documented negatives. ReStraV already uses DINOv2 temporal geometry, and the failed AEGIS model used a larger frozen DINOv2 with learned temporal derivatives and other branches. Thus “DINOv2 plus time” itself is not novel evidence that their failure is solved. A temporal-benefit claim would require a prospectively fixed appearance-only control; success of one fitted head alone cannot isolate its mechanism.

This proposal is narrower than the intended product. The [mini training audit](./TRAINING_SOURCE_AUDIT.md) found four generator folders and binary whole-video labels, no camera-family records, explicit conventional-CGI negatives, or verified mixed-interval supervision. A frozen representation and a small head cannot recover cropped/unsampled evidence or learn source truth absent from its labels. Independently documented CGI, camera edits/timelapse and brief generated inserts must remain decisive external gates. Our consumed tests cannot be relabeled as untouched validation, and the 30 reserved calibration sources stay protected. Even a strong within-archive result would be exploratory evidence, not proof of Instagram accuracy or calibrated confidence.
