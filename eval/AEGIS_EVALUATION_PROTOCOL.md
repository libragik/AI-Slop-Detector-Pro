## Why its public benchmarks are not independent validation

**Checkpoint selection used test-benchmark observations.** The README compares epoch 4 on AEGIS with epoch 7 on GenBuster and cites the latter's balance when explaining the chosen checkpoint. Published artifacts include GenBuster epoch-3 and epoch-4 ablations. The training script itself saves the best checkpoint by validation AUC; that does not erase later benchmark-informed selection or endorsement. [Selection discussion](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/README.md#%C3%B6nemli-kararlar-ve-gerek%C3%A7eler), [training checkpoint rule](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/train.py#L410), [epoch comparison artifact](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/results/phase2/ablation_genbuster_checkpoint_epoch004.json).

The author's named GenBuster test is **GenBuster-Bench++**, while our existing clips come from the earlier pinned **GenBuster-Bench** archive. Exact overlap has not been established or excluded. Our newly assigned development/calibration/holdout split cannot undo a released model's prior exposure to related public benchmark material. No results here may be labeled an untouched GenBuster test of Aegis.

**Training and testing use overlapping AIGVDBench source pools.** `build_final_dataset.py` includes 100 samples each from the extracted Gen2 and Luma directories. `ablation_eval.py` evaluates samples from those same directories without excluding training/validation membership. This contradicts a blanket claim that every named test collection never entered training. Without the actual training and evaluation indices, exact overlapping file counts cannot be asserted. [Training sources](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/build_final_dataset.py#L48), [AIGVDBench evaluation](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/ablation_eval.py#L485).

**The split code does not establish semantic independence.** It randomly splits files within each named dataset/generator source; it does not cluster capture sessions, creators, prompts, reference families, or byte/perceptual duplicates across datasets. The fresh-real helper excludes previously listed path strings, not related media or aliases. Incomplete local source descriptions and unpublished exact indices also prevent reproducing a verified exclusion audit from these scripts alone. [Train/validation split](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/build_final_dataset.py#L149), [fresh-real exclusions](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/build_fresh_real_test.py#L33).

**Calibration code can consume named test collections.** `build_calibration_set.py` collects from AEGIS Hard, AIGVDBench, and GenVideo real, with a Phase 1 default checkpoint. Its presence is not proof that this calibration was applied to the released Phase 2 checkpoint. It is a reason not to import a temperature, threshold, or confidence claim without establishing its actual provenance. [Calibration inputs and default checkpoint](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/build_calibration_set.py#L5).

## Fixed inference contract

1. Use only the pinned best checkpoint and main fused output. Do not compare epochs, individual branches, pairwise heads, temperatures, fitted thresholds, or ensembles on these observations. Auxiliary branch outputs may be saved as diagnostics, but cannot alter the declared decision.
2. Match the official raw-video **ablation** loader: 16 RGB frames, centered four-second window, `random_start=False`, bilinear resize to 224×224, and ImageNet normalization. For shorter clips, use the official whole-clip sampling behavior. This centered setting is already used by the authors' benchmark; the convenience CLI instead defaults to a random window. Preserve frame indices and times for every input. [Benchmark loader](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/ablation_eval.py#L228), [sampling and preprocessing](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/utils/video_io.py#L175).
3. Match benchmark threshold semantics: main fused sigmoid score **greater than or equal to 0.5** is positive. Save the corresponding raw logit and all nonfinite/missing output failures. The CLI uses a strict greater-than comparison; this protocol deliberately chooses the benchmark's inclusive comparator and must record it. Call the value an uncalibrated score, not an AI probability. [Benchmark metrics](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/ablation_eval.py#L62).
4. Retain the official quality eligibility checks: at least eight frames, shortest side at least 128 pixels, and at least one second. Report rejected or undecodable inputs as errors in the complete selected denominator. The stock OpenCV fallback silently repeats prior frames or inserts zeros when requested frames are missing; the evaluation adapter must detect and fail these cases rather than infer on fabricated observations. Legitimate repeated indices from sampling a short valid clip are different and must be recorded. [Quality and decode helpers](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/utils/video_io.py#L29).
5. Require the complete expected model state, strict key matching, verified checkpoint hash, and inference/eval mode. Never accept the CLI's random-weight fallback or its unrestricted pickle load. Architecture-only backbone initialization is acceptable only if the pinned checkpoint supplies every required learned tensor. Freeze **CPU-only FP32, four PyTorch threads, batch size 1**, the decoder, numerical settings, dependencies, and adapter source. No MPS comparison or extra model calls are part of this screen. Preserve the published learned computation, including its FFT-axis behavior. Compatibility work must not silently redesign the network.
6. Do not import the CLI's confidence labels. Its disagreement trigger exceeds the possible population variance of three sigmoid outputs, and its high-confidence language is not a calibration guarantee. [CLI interpretation](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/inference.py#L37), [disagreement computation](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/detector_model.py#L161).

Batch size is material to this source implementation: `fftshift` omits its dimensions after batch and time are flattened, so it shifts the frame-batch axis as well as spatial frequencies. With multiple videos this transfers frequency features between videos; with one video it rotates that video's temporal frequency features. The independent single-video screen preserves this computation at batch size one and does not claim equivalence to published batched metrics. A correction to FFT axes would be a distinct model computation requiring a new study, not an unnoticed portability fix. [Frequency encoder](https://github.com/MusapYildiz/ai_video_detection_benchmark/blob/d86a774fd971954a023e1cd00ed7ff5b2575e0d1/src/branches/pixel_branch.py#L196).

## Bounded development screen and stop rules

Maximum scope: **108 existing files**, with no new media generation or acquisition required for the cohort. Freeze all selected IDs, file hashes, manifest hashes, source/checkpoint/adapter hashes, and decision rules before inference. Neither the untouched 30-clip calibration allocation nor the consumed 75-clip holdout participates.

**Stage 1: three known-origin diagnostic controls.** Use exactly `eval/generated-origin-manifest.jsonl`: whole generated video, conventional CGI, and CGI with the two-second generated insert. Required results are positive, negative, positive respectively, with no processing errors. Any failure stops this candidate screen; retain and report all three selected results, including errors. This rule rejects the candidate for the intended application, not every use within its narrower advertised scope. These files share one generated parent and one CGI parent; they are not three independent sources. Centered sampling intersects the known insert location, so a hit cannot establish arbitrary-position short-insert sensitivity. Report how many sampled frames fall inside the declared interval without changing the window after seeing scores.

**Stage 2: original and quality-paired smoke set, only if Stage 1 passes.** Use exactly the 35 existing smoke originals, plus their 70 mild/severe derivatives: 23 author-labeled AI and 12 author-labeled real registered groups. Confirm every original is development and all derivatives retain its group. Run the whole declared stage; do not select examples or omit failures based on output. Require at least **17/23 AI positives in each quality stratum**, **zero of 12 real groups flagged in any variant**, and no unresolved processing failures. Abstentions/errors count as AI recall misses; report real-group errors alongside false flags rather than treating errors as negatives. No threshold fitting or follow-up branch/epoch search is part of this protocol.

Report original/mild/severe confusion counts, any-variant real false flags, complete selected denominators, processing errors, frame coverage, runtime, and raw-score distributions. Any registered-group bootstrap or paired interval remains conditional on undocumented source-independence assumptions; 105 rows are not 105 independent sources. The known-origin controls and author-labeled GenBuster diagnostics must stay separate in the report.

Passing these gates would justify a new, separately frozen evaluation with documented real capture and generation origins. It would not justify production integration, a confidence percentage, a reliable-Instagram claim, or a population accuracy estimate. Failing them ends this candidate as configured; preserve the failed run rather than tuning until it passes. Any later representation or sampling redesign needs a new preregistered study and fresh independent-source evidence.
