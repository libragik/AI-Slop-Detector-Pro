## Current behavior — evidence-2.10

- Sightengine and Gemini inspect the same downloaded/uploaded bytes, bound by a media hash. YouTube uses a bounded native-extractor download when the specialist is enabled; Instagram, TikTok, and X retain their identity checks.
- The specialist returns timestamped sample evidence. Repeated positive samples, isolated unresolved alerts, missing coverage, and request failures stay distinct. Adjacent samples are correlated; scores are not calibrated probabilities.
- Sightengine is the primary visual detector. Complete persistent specialist evidence produces AI indicators detected even when Gemini finds no indicators, remains inconclusive, or fails. Gemini disagreement is explanatory context and cannot veto those findings. Isolated-only flags or an incomplete specialist request yields Inconclusive while retaining the original findings. Both no-hit results may yield No clear AI indicators, explicitly without proving authenticity. Trusted AI provenance and explicit disclosures retain their separate meanings.
- The report shows a specialist timeline and raw scores on demand. Gemini observations remain attributed to Gemini; no specialist result is converted into invented Gemini narration or a percentage confidence.
- Credentials remain server-side. Sightengine requests have no automatic retry, reject redirects, enforce exact byte identity, cap response size/time and operations accounting, and allow two concurrent scans within a server process, with asynchronous jobs polled every three seconds. This is not a distributed account-wide limiter.
- All supported inputs up to three minutes and 500 MB reach the specialist. Short/small inputs use synchronous processing; videos at least 60 seconds long use asynchronous jobs, and files at least 50 MB use the signed Upload API before job submission. Larger files stream unchanged from the validated local file. Both Sightengine-hosted and provider-returned signed S3 storage URLs are supported. Upload asset IDs and analysis-job IDs are tracked separately, with each poll bound to the returned job ID and submission request ID. The specialist upload/job lifecycle allows ten minutes, with a separate five-second stop attempt on failure. Gemini large-file uploads may take up to five minutes within their ten-minute lifecycle; individual inference calls retain their existing deadlines. The smaller numbers are endpoint-routing boundaries, not input rejection limits. Half-second sampling cannot exclude AI between samples.
- Cache fingerprints include specialist configuration and the combined decision policy. Failed or incomplete specialist reports, missing specialist evidence when configured, and mismatched source hashes are not reusable cached results. The upload notice names both providers.

## Historical agreement-policy comparison and execution repairs

The preserved Gemini adapter returned 24 of the same 25 cases. One hung request was interrupted after 372 seconds and remains a technical error with unknown final billing; it was not rerun. Offline replay through the then-current agreement combiner detected 5/12 publisher-labeled AI cases, the same as Gemini alone. Five Gemini clear misses became Inconclusive. Negative false AI alerts were 0/12, but only 4/12 negatives received a clear result; the other eight were Inconclusive. Severe-quality AI detection was 0/4. This reduces false reassurance without establishing improved recall. [Paired report](../eval/runs/sightengine-temporal-screen-v2-paired-summary/REPORT.md).

A separate live YouTube request also hung. Inspection of the installed Gemini SDK found that Interactions calls did not inherit the constructor HTTP timeout. Explicit per-call timeouts, abort signals, and independent promise deadlines now bound provider requests; upload, file polling, and cleanup are bounded too. The complete uploaded Gemini lifecycle is limited to 180 seconds, reserving five seconds for cleanup. Content Credential inspection has a ten-second reporting deadline. Real provider testing also caught an SDK upload regression: adding per-call HTTP options replaced the resumable upload defaults and generated a duplicate API-version path. A native implementation of the [documented Files upload protocol](https://ai.google.dev/gemini-api/docs/files) now retains the required headers, streams the original file, rejects redirects and unexpected session origins, and cancels both setup and transfer. The pipeline waits for all bounded provider branches before releasing its queue slot, including after a fast provider failure. These execution fixes do not change the frozen comparison adapter or rescue its interrupted attempt.

Real browser testing also exposed two execution edge cases. Waiting for cancellation of an unread cloned response can stall teardown, so cancellation is requested without awaiting that promise while request reads remain bounded. A generated review-window offset exceeded protobuf Duration's nine fractional digits and caused an adjudication HTTP 400; offsets now use canonical duration strings and matching receipt bounds. The preserved failing adjudication completed after that repair. Neither fix changes sampling, model prompts, scoring thresholds, or the original frozen evaluation outcomes.

The prior evidence-2.9 production build passed 381 tests, lint, typecheck, and build. Fresh Instagram, YouTube, TikTok, X, and multipart upload requests all completed, with matching source bindings and fingerprint `6cf0e22eafe74b03c7885a5c45fc1bef4d47a39d42f2c7b2728e85e44960c684`. Under that prior policy, the exact user Reel returned Inconclusive with 19/23 specialist flags. The receipt-backed Veo upload also returned Inconclusive despite 16/16 specialist flags and three completed Gemini passes. That remains an AI non-detection by the combined rule, not evidence that request repairs solved accuracy. [Final request and browser evidence](./VERIFICATION.md).

## What remains unproven

Agreement between providers is not proof and can share errors. The curated controls and publisher labels do not establish population accuracy. Any rule's abstentions must be counted as AI non-detections rather than quietly removed from its recall denominator. The new primary-specialist decision can recover detections suppressed by Gemini, but it also retains specialist false alerts. Replaying known cases is a policy regression check, not new accuracy evidence. Fresh sources, mixed and brief inserts, realistic compression, and more generator families still require independent evaluation. No new confidence percentage or reliability claim is justified by this integration.

The running app and final network/browser checks are documented in [verification](./VERIFICATION.md). The original failed tests and frozen artifacts remain preserved.

## Provider limits and API choice

Sightengine Pro advertises 500 MB videos. The earlier app only implemented direct synchronous requests and mistakenly presented their limits as overall service limits. The [provider size/length FAQ](https://sightengine.com/faq/recommended-video-dimensions-and-length), [Upload API](https://sightengine.com/docs/upload-api), and [job status API](https://sightengine.com/docs/interact-with-video-moderation-jobs) document the paths now used for larger and longer inputs. The [plan comparison](https://sightengine.com/pricing) lists the 500 MB Pro allowance. No account upgrade or new keys are needed.

Final software and real request evidence for this policy are recorded in [the current verification section](./VERIFICATION.md). Earlier request attempts are retained separately; an HTTP 200 response alone does not count as successful specialist processing.
